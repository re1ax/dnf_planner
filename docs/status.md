# 恢复状态与来源边界

本项目是可读、可编译、可运行的功能重建，不是作者原C++/转换器源码正文逐字找回。

## 已有验证

- 原转换器157项golden：115接受、42拒绝，对应输出和诊断在既有回归中一致。
- 作者Blocks输入转换得到相同Prolog；在同一AL上原/新规划器得到相同7步计划，且交叉验证通过。
- 2026-10-17新增300个小型AL域：61有计划、239无计划结果一致，122次交叉计划验证通过。
- 原 `mult5zsic.pl` 完整保留；前处理器在SWI兼容层运行，提供独立的faithful/repaired模式。

这些是原评估结果摘要，完整逆向工作文件不随源码发布。小型样例结果不构成大规模性能或全部语义等价证明。

## 尚未恢复或验证完整

1. 扩展转换器探针186例中有28例实质输出差异，主要涉及复合UNKNOWN的对立式、NOT节点分派及空前置/效果。此发布整理不修复这些算法差异，也未将这些失败例伪装成已通过回归。
2. 没有原SICStus运行oracle。SWI的方言兼容与列表顺序角落未全面比较。
3. mixed atom/list oneof与no_oneof的组合仍可能序列化失败；固定5层依赖传播未证明任意长链正确；拆分目标仅分别求解，没有联合计划验证。
4. 规划器的每步完整规范化、目标clause约简、值型集合/缓存及资源限制与原自适应约简、位图/共享状态等实现存在差异。
5. 某些原版接受的量词、复合否定等输入本身会输出非标准或有问题的Prolog；不能把接受输入等同于支持标准PDDL语义。

原 `combine_conditions(L,L)` 标记待实现，部分辅助入口含未定义谓词。保留原文本不代表这些原作者未完成的功能已经完成。

## 此次发布整理的变化

- 保留核心源文件、必需语法表、离线包、参考输入和golden；移除二进制、缓存、运行结果、历史脚本和大型逆向证据。
- 测试临时目录由原逆向工作区路径改为仓库的 `runs/preprocessor-tests/`。
- golden索引仅将原本机目标路径改为原件名称描述；输入/输出golden及原件哈希保留。
- 不修改规划器、转换器和前处理算法。
